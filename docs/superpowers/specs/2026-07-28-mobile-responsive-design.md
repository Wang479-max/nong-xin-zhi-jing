# 农芯智境移动端全模块响应式设计

**日期：** 2026-07-28  
**状态：** 已获用户批准，待书面规格复核  
**范围：** 农芯智境智慧农业管理系统的手机端与平板端适配  
**核心约束：** 1024px 及以上电脑端的现有布局、尺寸和交互保持不变

## 1. 背景与目标

当前系统已形成完整的电脑端管理界面，包含侧栏、顶部信息区、数据看板、农田监测、地块管理、AI 识别、农业知识库、行业资讯、服务市场、用户反馈、设置、农事日历、天气与 3D 农场等功能。现有小屏布局仍大量沿用电脑端信息密度、固定尺寸和宽表格，导致部分内容在手机上显示不完整或操作困难。

本次改造采用已批准的“方案 A”：参考手机端 B 站的信息组织方式，但不复制其品牌视觉。手机端使用紧凑顶栏、横向分类、内容卡片和五项底部导航；所有业务模块都必须可进入、可完整显示并能完成主要操作。电脑端继续使用现有侧栏、顶部信息区和大屏布局。

## 2. 成功标准

只有同时满足以下条件，任务才视为完成：

1. 首页、农田监测、地块管理、AI 识别、农业知识库、行业资讯、服务市场、用户反馈、设置及相关工具模块均可在手机端进入。
2. 所有模块在 320px、375px、390px 和 430px 宽度下没有非业务需要的整页横向滚动，内容不被裁切。
3. 搜索、筛选、查看详情、表单填写、图片上传、弹窗关闭、模块切换等主要操作可以通过触摸完成。
4. 页面内容不会被刘海、安全区、浏览器底栏、虚拟键盘或固定底部导航遮挡。
5. 768px 平板边界没有布局断层；1024px 及以上电脑端与改造前保持一致。
6. 浅色/深色模式、角色权限、数据请求、业务状态和中英文切换继续正常工作。
7. 类型检查、组件测试和生产构建全部通过。

## 3. 断点策略与桌面端保护线

### 3.1 断点定义

- **320–767px：手机端。** 启用方案 A 的移动外壳和移动内容规则。
- **768–1023px：平板端。** 保留抽屉式导航，内容列数和弹窗尺寸按平板空间调整。
- **1024px 及以上：电脑端。** 保持现有侧栏、顶部信息区、卡片列数、3D 入口、快捷键和桌面交互不变。

### 3.2 隔离原则

移动端新增独立的导航外壳组件，通过响应式显示条件挂载。现有桌面侧栏和顶栏不重写、不复用移动端尺寸，也不修改电脑端布局分支。业务页面优先采用 CSS 响应式重排；只有导航、全屏功能面板和移动弹窗等交互结构明显不同的部分才创建移动专用组件。

任何通用样式调整必须满足以下条件：

- 默认值保持现有电脑端表现；
- 移动和平板变化写在明确的小屏断点内；
- 不通过全局缩放或整体压缩模拟手机布局；
- 不修改现有电脑端断点语义。

## 4. 手机端信息架构

### 4.1 顶部区域

手机端顶部区域保持紧凑，并按以下顺序组织：

1. 品牌图标；
2. 全局搜索入口；
3. 用户头像或账户入口；
4. 当前模块的横向分类栏。

分类栏只服务当前模块，保持单行、允许水平滑动，当前项自动滚入视野。它不会把所有系统模块堆在同一行，也不会造成页面整体横向溢出。

### 4.2 底部导航

底部固定五个入口：

1. 首页；
2. 农田监测；
3. 地块管理；
4. AI 识别；
5. 全部。

底部导航适配系统安全区。触摸区域不小于 44×44px。切换模块继续复用现有 `activeTab`、`handleNavigate` 和角色权限，不建立第二套业务路由。

### 4.3 “全部”功能面板

“全部”打开全屏功能面板，并分为“业务功能”和“工具与账户”两组。功能包括：

- 农业知识库；
- 行业资讯；
- 服务市场；
- 用户反馈；
- 农事日历；
- 天气详情；
- 消息通知；
- 设置；
- 新手引导；
- 退出登录。

面板继续沿用现有角色权限过滤。普通用户、农业专家和管理员只看到自己有权限访问的入口。

### 4.4 模块内分类

模块内部采用横向分类，例如：

- 首页：概览、环境、作物、任务、预警；
- 监测：实时、趋势、设备、告警；
- 地块：列表、地图、作业、档案；
- AI：拍照、上传、历史。

具体分类只映射现有功能，不新增本次范围外的业务能力。

## 5. 页面类型适配规则

### 5.1 数据看板与卡片

- 核心指标保持双列，确保首屏信息密度；
- 复杂分析卡、日志、天气、任务、雷达图和长内容改为单列；
- 缩小手机端卡片内边距和装饰留白，但不降低正文可读性；
- 卡片中的主要数值、状态和操作优先展示，辅助说明允许折叠或下移；
- 图表容器使用可用宽度，不依赖固定像素宽度。

### 5.2 表格、清单与档案

- 地块、设备、操作记录和识别历史等宽表格在手机端转换为信息卡列表；
- 每张卡展示主标识、关键字段、状态和一个主要操作；
- 次要操作收进“更多”菜单；
- 筛选项可横向滚动，但页面本身不得横向滚动；
- 平板端可保留简化表格，手机端不要求用户左右拖动才能读取完整行。

### 5.3 表单、弹窗与设置

- 表单字段改为单列；
- 输入控件高度至少 44px，标签始终可见；
- 复杂弹窗改为全屏页面或底部抽屉；
- 主操作按钮固定在安全区上方；
- 虚拟键盘弹起时，当前输入字段和错误提示仍可见；
- 设置页的三列区域在手机端转为分组列表。

### 5.4 地图、3D 与图表

- 地图占满可用内容宽度；
- 地块详情通过可拖动底部面板展示；
- 地图控件保留必要的定位、缩放和图层操作，并扩大触摸区域；
- 图表减少小屏坐标文字，支持触摸提示；
- 3D 农场保留全屏入口，隐藏仅依赖鼠标悬停的控件；
- 对不支持 WebGL 或性能不足的设备显示明确的降级提示和返回入口，不能出现空白页面。

### 5.5 AI 识别与上传

- 拍照、相册上传、诊断过程和识别结果按纵向流程排列；
- 图片对比操作支持手指拖动；
- 上传进度、失败原因和重试入口不遮挡主操作；
- 识别历史在手机端使用卡片列表；
- 相机权限或文件选择失败时显示可恢复的错误状态。

### 5.6 知识库、资讯与服务市场

- 知识和资讯列表使用双列图文卡；极窄屏下允许退化为单列；
- 详情页使用单列阅读布局；
- 搜索和分类吸顶；
- 知识目录、资讯侧栏和筛选区域在手机端变为底部面板；
- 服务购买流程改为分步全屏操作，价格、权益和确认按钮保持可见；
- 长标题、来源、用户名和地块名允许换行或截断，不得撑破卡片。

## 6. 组件边界与数据流

### 6.1 移动外壳组件

计划新增以下职责清晰的组件：

- `MobileAppShell`：组织手机顶栏、内容区、底部导航和安全区；
- `MobileTopBar`：品牌、搜索和账户入口；
- `MobileSectionTabs`：当前模块的横向分类；
- `MobileBottomNav`：四个高频模块和“全部”入口；
- `MobileMoreSheet`：次级模块、工具和账户操作；
- 通用移动弹窗或底部面板基元：承载详情、筛选和次级操作。

这些组件只负责布局和导航，不复制数据请求、角色判断或模块业务状态。

### 6.2 复用现有数据流

移动端和电脑端共同使用：

- `activeTab` 与现有模块切换逻辑；
- `handleNavigate` 与跨模块查询参数；
- 当前用户与角色权限；
- 现有 `DataService` 请求；
- 深色模式、语言、通知、设置和账户状态；
- 各业务组件原有的事件处理与错误反馈。

移动外壳触发的导航最终进入现有 `renderContent()`，因此同一模块不会出现手机和电脑两套数据状态。

### 6.3 状态保持

模块切换时应尽量保留现有筛选、选中的地块和滚动位置。对已有组件无法自然保持的状态，优先提升状态到现有页面边界，而不是在移动外壳中复制。

## 7. 异常处理与可访问性

### 7.1 异常与边界状态

- 网络失败：显示错误说明和重试按钮；
- 空数据：显示与模块语义一致的空状态；
- 加载中：使用不会引发布局跳动的骨架或进度状态；
- 超长文本：按内容类型换行或截断；
- 横竖屏切换：布局重新计算后保持可用；
- 虚拟键盘：不遮挡焦点字段和提交按钮；
- 刘海与系统手势区：使用安全区内边距；
- 地图或 3D 不可用：提供降级说明和返回路径。

### 7.2 可访问性

- 可点击区域不小于 44×44px；
- 不把鼠标悬停作为唯一操作方式；
- 图标按钮提供可访问名称；
- 弹窗打开后管理焦点，关闭后返回触发点；
- 底部导航和横向分类提供当前项状态；
- 支持键盘操作和屏幕阅读器的基本语义；
- 动画遵循用户的减少动态效果设置。

## 8. 测试策略

### 8.1 测试驱动开发

实现过程遵循测试先行：

1. 先为移动导航显隐、角色过滤、模块切换和功能面板行为编写失败测试；
2. 运行测试并确认因缺少目标行为而失败；
3. 编写最小实现使测试通过；
4. 再进行样式整理和组件拆分；
5. 每轮重构后重新运行测试。

### 8.2 自动化测试范围

需要覆盖：

- 手机端显示移动外壳，电脑端显示现有外壳；
- 底部导航正确切换现有模块；
- “全部”面板按角色显示正确入口；
- 面板、弹窗和返回操作可关闭并恢复焦点；
- 表格型内容在手机端使用卡片表现；
- 手机端不存在会强制撑宽页面的固定容器；
- 深色模式与语言切换仍能传递到移动组件；
- 类型检查和生产构建通过。

测试工具计划使用 Vitest、Testing Library 和 jsdom；若项目中尚未安装，将作为开发依赖加入，并通过最小配置接入。

### 8.3 人工设备验收

至少在以下宽度进行逐模块检查：

- 320px；
- 375px；
- 390px；
- 430px；
- 768px；
- 1024px；
- 1440px。

人工验收覆盖：

- 首页；
- 农田监测；
- 地块管理；
- AI 识别；
- 农业知识库；
- 行业资讯；
- 服务市场；
- 用户反馈；
- 设置；
- 农事日历；
- 天气与通知；
- 3D 农场入口及降级状态。

每个模块至少验证进入、滚动、搜索或筛选、查看详情、主要操作和返回。还需检查浅色/深色、管理员/农业专家/普通用户和中文/英文。

## 9. 回归保护与现有工作区

工作区当前存在用户对以下文件的未提交修改：

- `src/components/KnowledgeBase.tsx`；
- `src/components/NewsModule.tsx`；
- `src/lib/utils.ts`。

实施时必须保留并兼容这些修改，不得覆盖、还原或把它们混入无关提交。涉及知识库、资讯或工具文件时，应先读取当前工作树版本，进行最小范围编辑，并通过差异检查确认用户改动仍然存在。

电脑端回归保护以 1024px 和 1440px 为主要对比宽度。任何移动适配样式若影响这些宽度，必须视为缺陷并修正。

## 10. 非目标

本次不包含：

- 重做电脑端视觉设计；
- 改变后端 API 或数据库结构；
- 新增现有系统不存在的业务模块；
- 将网页改造成原生 iOS 或 Android 应用；
- 模仿 B 站品牌颜色、图标、文案或其他受保护的品牌元素；
- 与移动端适配无关的大规模重构。

## 11. 交付内容

最终交付应包括：

1. 手机端方案 A 的全局导航与全部功能面板；
2. 全模块响应式布局和触控交互；
3. 平板边界适配；
4. 电脑端布局保护；
5. 移动导航和关键交互的自动化测试；
6. 类型检查、测试、生产构建和人工宽度验收记录。
