# 安全 XLSX 导出替换设计

日期：2026-07-26
状态：待用户书面确认

## 1. 背景与目标

生产依赖安全审计确认 `xlsx@0.18.5` 存在原型污染与正则表达式拒绝服务高危漏洞，且 npm 官方审计没有可用修复版本。项目只在农田监测页面使用该库生成一张 Excel 工作表。

本次改动必须：

- 完全移除 `xlsx` 生产依赖及其高危告警；
- 保留现有“导出 Excel”入口、弹窗、通知、文件名和 `.xlsx` 文件格式；
- 保留报表标题、地块与作物信息、生成时间、安全说明、数据表头和四处合并单元格；
- 不改变其他前端页面、后端接口和业务数据；
- 不引入新的生产依赖。

## 2. 方案选择

采用项目已有的 `jszip` 与 `file-saver`：

1. 将工作簿、工作表、样式、关系和内容类型生成为标准 Office Open XML；
2. 使用 `JSZip` 打包为 `.xlsx` Blob；
3. 使用 `file-saver` 触发浏览器下载。

不采用 ExcelJS，因为会增加新的大型依赖及其供应链审计面；不降级为 CSV，因为 CSV 无法保留工作表、合并单元格和现有 `.xlsx` 用户体验。

## 3. 模块边界

新增独立模块 `src/lib/xlsxExport.ts`，职责仅包括：

- 接收工作表名称、二维单元格数据、合并区域和可选列宽；
- 对 XML 文本和属性进行严格转义；
- 将文本写为 `inlineStr`，将有限数字写为数值单元格；
- 生成并返回合法 XLSX Blob；
- 调用下载依赖保存指定文件名。

农田监测组件继续负责：

- 查询历史记录；
- 根据用户勾选项组装报表数据；
- 生成现有中文标题和文件名；
- 显示现有成功、失败和无数据通知。

组件不再直接了解 OOXML 或压缩包结构。

## 4. 文件兼容与安全规则

- 工作表名称去除 Excel 禁止字符 `\ / ? * [ ] :`，最长 31 个字符；清理后为空时使用“监测数据”。
- 所有文本以 XML 安全的内联字符串写入，不解析 HTML，不生成公式，避免以 `=`、`+`、`-`、`@` 开头的数据形成公式注入。
- 数值仅在值本身是有限 JavaScript number 时写为数值单元格；现有 `toFixed` 字符串保持原显示精度。
- 生成包只包含 XLSX 所需的固定文件路径，不接受用户控制的压缩包路径。
- 四个现有合并区域保持为 `A1:J1`、`A3:J3`、`A4:J4`、`A5:J5`。
- 导出失败继续走现有错误通知，不向用户显示内部 XML、堆栈或数据内容。

## 5. 测试与验收

测试先行，新增独立单元测试：

- 解压生成的 Blob，验证 XLSX 必需文件完整；
- 验证工作簿关系、工作表名称和内容类型正确；
- 验证中文、特殊字符经过 XML 转义后可以还原；
- 验证四个合并区域和数据起始行与旧报表一致；
- 验证文本不会成为公式；
- 验证非法或过长工作表名称被安全清理；
- 验证浏览器下载函数收到原文件名和 XLSX Blob。

回归门禁：

- 农田监测组件不再导入 `xlsx`；
- `package.json` 与锁定文件不再包含直接依赖 `xlsx`；
- 全量 Vitest、TypeScript 和生产构建通过；
- `npm audit --omit=dev --audit-level=high` 不再报告高危或严重生产漏洞；
- 构建后的页面外观与交互入口保持不变。

## 6. 回滚

改动作为独立提交保存。如生成文件在目标 Excel/WPS 环境中出现兼容问题，可回退该提交恢复旧实现；正式上线前必须完成 Excel 与 WPS 各一次人工打开验收，不能以重新引入存在高危漏洞的 `xlsx` 作为长期方案。
