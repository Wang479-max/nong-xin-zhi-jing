# 农芯智境模块化单体 SaaS 设计

## 1. 目标

在保留现有 React、Three.js、Cesium、AI 识别、知识库和监测界面的基础上，把当前演示型后端升级为可部署、可注册、可隔离、可购买和可审计的多租户 SaaS。

首个可交付版本必须满足：

- 注册用户自动获得免费基础版。
- 所有业务菜单均可见，未购买模块允许查看介绍或示例，但不能执行受控操作。
- `admin` 是平台测试管理员，拥有全部功能和无限额度。
- 权限和套餐限制由后端强制执行，不能靠修改浏览器数据绕过。
- 用户、组织、订单、权益和业务数据写入 PostgreSQL。
- Redis 只承担限流、短期缓存和会话辅助，不作为订单或权益事实来源。
- 竞赛环境支持模拟支付；生产支付使用同一订单状态机，但必须验证支付回调。

## 2. 交付边界

本次采用渐进迁移：新增 `/api/v1` 正式接口并接管认证、组织、权益和订单；原 `/api` 业务接口在迁移期间继续工作。每个旧接口迁移时必须增加登录、租户和权益校验，最终移除对前端 `username` 参数的信任。

不在首个版本实现：微服务、Kubernetes、复杂分布式事务、真实微信或支付宝商户配置、超大规模时序数据平台。

## 3. 架构

系统仍作为一个 Node.js 进程发布，但后端按业务边界拆分：

- `auth`：注册、登录、刷新、退出、密码哈希。
- `organizations`：组织、成员、角色和数据边界。
- `entitlements`：套餐、模块、额度、到期和管理员覆盖。
- `billing`：商品目录、订单、支付事件和权益发放。
- `farms`：农场、地块和基础业务资源。
- `devices`：设备、监测和控制。
- `ai`：AI 请求、配额和结果。
- `audit`：安全及业务审计。

模块通过明确的服务接口协作，不能直接修改其他模块的私有表。

## 4. 身份和租户

注册时创建用户、个人组织和 `owner` 成员关系。注册请求不能指定管理员或农业专家角色。

平台角色：

- `platform_admin`：平台运营管理。
- `user`：普通平台用户。

组织角色：

- `owner`
- `admin`
- `expert`
- `operator`
- `viewer`

每个业务请求从经过验证的访问令牌取得 `userId`，再根据成员关系确定 `organizationId` 和角色。业务接口不得使用请求体或查询参数中的用户名决定身份。

密码使用 bcrypt 哈希。访问令牌短期有效；刷新令牌只以哈希形式保存，使用 HttpOnly、Secure、SameSite Cookie 传输。竞赛阶段允许通过显式配置启用管理员演示入口，生产环境默认关闭。

## 5. 套餐和权益

功能键初期包括：

- `monitoring.basic`
- `monitoring.realtime`
- `ai.diagnosis`
- `digital_twin.advanced`
- `analytics.advanced`
- `device.control`
- `team.members`
- `deployment.private`

权益由套餐和已购买模块共同产生。最终判断规则：

`管理员覆盖 + 有效套餐功能 + 有效增值模块 - 已到期或退款权益`

数量限制独立保存：地块数、设备数、成员数、AI 月额度、数据保留天数。所有受控 API 使用统一 `requireFeature` 或 `requireQuota` 中间件。前端门控只负责展示体验。

免费版默认提供 1 个组织、2 个地块、基础监测、知识库和每月 5 次 AI 识别。所有菜单仍显示，锁定模块提供说明、示例和购买入口。

## 6. 服务市场和订单

商品目录包括套餐、功能模块、AI 次数包、硬件和人工服务。价格只能从服务端目录读取。

订单状态：

- `pending`
- `paid`
- `fulfilled`
- `cancelled`
- `refunded`
- `expired`

创建订单必须使用幂等键。支付事件必须记录提供商事件 ID，并在数据库事务内完成“确认支付、发放权益、写审计日志”。重复回调不得重复发放权益。

模拟支付只在 `PAYMENT_MODE=mock` 时启用。生产回调必须验证签名、商户、金额、币种和订单状态。

## 7. 数据模型

核心表：

- `users`
- `user_credentials`
- `organizations`
- `organization_members`
- `refresh_sessions`
- `plans`
- `features`
- `plan_features`
- `products`
- `subscriptions`
- `entitlements`
- `usage_counters`
- `orders`
- `order_items`
- `payment_events`
- `audit_logs`

业务表逐步增加 `organization_id`。所有数据库迁移使用版本化 SQL，并可重复、安全地执行。

## 8. 用户界面

登录后的菜单对所有注册用户可见。每个入口展示 `免费`、`试用`、`专业版` 或 `已购买` 状态。

新增：

- 我的订阅与额度。
- 统一升级弹窗。
- 服务市场订单详情。
- 组织与成员管理。
- 平台管理员运营后台。

现有视觉风格、数字孪生、仪表盘和业务页面主体保持不变。

## 9. 部署

腾讯云 Ubuntu 22.04 上使用：

- Nginx 监听 80/443。
- Node.js 22 LTS 应用监听 `127.0.0.1:3000`。
- PostgreSQL 监听 `127.0.0.1:5432`。
- Redis 监听 `127.0.0.1:6379`。
- systemd 管理应用进程。

安全组仅开放 80、443，以及限定来源 IP 的 22。3000、5432、6379不得公网开放。

数据库使用非超级用户。每日备份使用压缩格式，并加密上传腾讯云 COS；保留日、周、月多个周期并定期执行恢复演练。

## 10. 错误与降级

- PostgreSQL 不可用时，正式写请求失败并返回统一错误，不能静默写入浏览器本地数据。
- Redis 不可用时，核心登录和读操作可以降级，限流使用进程内保守策略。
- AI 服务不可用时返回明确的暂不可用状态，不消耗成功额度。
- 支付回调处理失败时保持订单可重试，不产生半发放权益。
- 演示数据和离线模拟只在显式演示配置中启用。

## 11. 测试与验收

测试必须覆盖：

- 注册不能自选管理员角色。
- 密码不会明文存储。
- 登录、刷新和退出生命周期。
- 普通用户不能访问其他组织数据。
- 免费用户可以看到模块但受控 API 返回 403。
- 模拟支付后权益立即生效。
- 重复支付事件只发放一次权益。
- 到期或退款后权益撤销。
- `admin` 无条件通过功能和额度校验。
- 数据库迁移、备份与恢复。

正式验收还包括类型检查、构建、关键端到端流程、负载测试和 OWASP 安全检查。
